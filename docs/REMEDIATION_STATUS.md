## How to read it

Status words (one per item; "partly" is added where the item is closed only in part):

| Status | Meaning |
|---|---|
| Fixed in database | The fix is a migration. No screen change was needed |
| Fixed in frontend | The fix is code under `app/`, `features/`, `components/`, `lib/` or `next.config.ts` |
| Fixed in both | A migration and the screens that use it |
| Documented limit | Not closed on purpose; the limit and the way to close it are written down |
| Owner action in a dashboard | Only the owner of the Supabase, Vercel, Google or GitHub account can do it |
| Not done | Nothing, or only a design, exists |
| Not applicable | The register line does not describe the code (already built, or stale) |

Where things are written:

- Migrations are in `supabase/migrations/`. "Release" says where the file sits in `RELEASE_ORDER.md`: **section 1** (apply before the new frontend: it only adds) or **section 3** (apply only after the new frontend is live: it removes a privilege or refuses something the deployed frontend still does).
- SQL suites are `supabase/tests/<name>.test.sql`, named here by `<name>`; `*.sh` are two-session scripts in `supabase/tests/concurrency/`. Unit tests are `tests/<name>.test.mjs`, component tests `tests/component/<name>`, API-level end-to-end suites `scripts/e2e/tests/<name>`, browser specs `tests/browser/specs/<name>`.
- A dagger (†) after a test means it needs the real test Supabase project and was **not run for this page**. Everything without a dagger was run on 28 Nov 2026 (see "What was run for this page").
- "No test found" means exactly that: `supabase/tests`, `tests`, `scripts/e2e` and `tests/browser` were searched for the behaviour and none was found.
